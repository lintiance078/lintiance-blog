# ASCII 字符画生成指南：从像素灰度到字符映射的算法原理

ASCII 字符画的本质是将图像的每个局部区域映射到一个字符，利用不同字符的视觉密度来模拟灰度。在终端中，字符是等宽的，所以每个字符单元天然形成了一个"像素块"。

## 转换算法的核心步骤

### 1. 灰度计算

对于彩色图片，首先需要将 RGB 转为灰度值。常用的加权公式是感知亮度公式（luminance），因为它考虑了人眼对不同颜色的敏感度差异：

```
Gray = 0.299 * R + 0.587 * G + 0.114 * B
```

绿色通道的权重最高（0.587），因为人眼对绿色最敏感。简单地取 `(R+G+B)/3` 会产生不准确的结果，红色和蓝色在视觉上会比实际更亮。

### 2. 字符密度映射

这是 ASCII 转换的核心。不同字符在视觉上占据的空间比例不同，形成了一个从"密"到"疏"的梯度。常用的字符集按密度排序：

```
@  # 密度最高，几乎全黑
%  # 较多笔画
#  # 高密度
*  # 中等偏密
+  # 中等
=  # 中等偏疏
-  # 低密度
:  # 极低密度
.  # 最低密度，几乎空白
   # 空格，纯白
```

映射逻辑：灰度值 0（黑色）映射到 `@`，灰度值 255（白色）映射到空格，中间值线性映射到对应字符。实际实现中，可以将字符集定义为数组，用 `charIndex = Math.floor(gray / 255 * (charset.length - 1))` 计算索引。

### 3. 对比度和亮度调整

原始图片的灰度分布可能集中在某个区间，导致字符画缺乏层次。通过对比度拉伸可以改善：

```javascript
// 伪代码：对比度调整
function adjustContrast(gray, contrast, brightness) {
  let adjusted = (gray - 128) * contrast + 128 + brightness * 128;
  return Math.max(0, Math.min(255, adjusted));
}
```

- `contrast = 1.0` 为原始对比度，`> 1.0` 增强对比度，`< 1.0` 降低对比度
- `brightness = 0` 为原始亮度，正值变亮，负值变暗

## 批量转换的实现考量

在使用 TUI 工具进行批量转换时，有几个工程细节值得注意：

1. **宽高比补偿**：终端字符通常高宽比约为 2:1（一个字符的高度约等于两个字符的宽度），因此在计算输出尺寸时需要补偿，否则图片会被纵向拉伸
2. **文件大小权衡**：ASCII 输出是纯文本，但对于大图片，生成的文本文件可能达到几 MB，考虑是否需要在输出中保留换行符一致性
3. **原图处理策略**：批量转换会删除原图片文件，这是为了节省磁盘空间，但建议在脚本中默认要求 `--confirm` 参数来防止误操作

## 网页渲染

字符画在网页上使用 `<pre>` 标签渲染，配合等宽字体。关键 CSS：

```css
pre.ascii-art {
  font-family: 'JetBrains Mono', 'Fira Code', monospace;
  line-height: 1.15;  /* 紧凑行高，避免字符间出现间隙 */
  font-size: 8px;     /* 小字号增加"分辨率" */
  letter-spacing: 0;
}
```

暗色模式下白色字符在黑色背景上对比度最佳，这也是为什么大多数 ASCII 艺术工具默认输出白色文本。

ASCII 字符画是图像处理和字符编码的一个有趣交叉点。理解其背后的算法原理，不仅能更好地使用工具，也能在需要自定义转换逻辑时做出正确的技术决策。
