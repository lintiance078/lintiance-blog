# 黑客文章详情页门禁验证 - 测试用例

## 测试目的
验证未授权用户无法直接访问黑客文章详情页，门禁机制（Access Gate）正确生效。

## 测试环境
- 本地开发服务器：`http://localhost:4321`
- 测试日期：2026-08-05
- 密钥：`hunter2`（djb2 哈希本地验证）

## 门禁机制说明
- 黑客文章详情页包含 `hacker-post-gate` 门禁组件和 `article[data-post-type="hacker"]` 文章内容
- 未激活黑客模式时：门禁显示（`🔒 访问受限`），文章内容隐藏（`display:none`）
- 激活黑客模式后：门禁隐藏，文章内容显示
- 页面刷新后：黑客模式重置，门禁恢复
- 验证方式：本地 djb2 哈希比对，无网络请求，密钥原文不出现在浏览器源码中

**操作**：在普通模式下，直接访问 `http://localhost:4321/posts/hacker-0-system-log/`

- 文章标题可见

**实际结果**：✅ 通过

gateComputedVisible: false

## 测试用例 6：HTML 源码层面门禁验证（服务端渲染检查）

**操作**：使用 `curl` 直接获取黑客文章页面的 HTML 源码，不经过浏览器渲染

**预期结果**：
- HTML 源码中包含 `id="hacker-post-gate"` 的完整门禁 DOM 元素
- HTML 源码中包含 `data-post-type="hacker"` 的文章内容，且 `style="display:none"`
- 门禁在服务端渲染阶段就已生成，**不依赖客户端 JS 执行**

**实际结果**：✅ 通过
```
--- 黑客文章 hacker-0-system-log ---
HTML 中门禁元素: <div id="hacker-post-gate" class="hacker-post-gate">
门禁标题: <h2>访问受限</h2>
门禁提示: 在设置面板中连续点击站点名称 5 次...
文章元素: <article class="article" data-post-type="hacker" style="display:none">
文章标题: [SYS] 系统日志 #001 - 初始化

--- 结论 ---
门禁在 SSR 阶段已生成，客户端即使禁用 JS 也无法绕过
```

## 测试用例 9：djb2 哈希验证机制正确性验证

**操作**：使用 Node.js 独立计算密钥的 djb2 哈希值，与 HTML 中嵌入的哈希值对比

**预期结果**：
- 正确密钥 `hunter2` 的 djb2 哈希 = HTML 中 `data-hash` 的值
- 错误密钥 `wrongkey` 的 djb2 哈希 ≠ `data-hash` 的值

**实际结果**：✅ 通过
```
--- 哈希计算 ---
hunter2  → djb2("hunter2")  = 1650179405
wrongkey → djb2("wrongkey") = 2695479675

--- HTML 中嵌入的哈希 ---
<span id="hacker-key-hash" data-hash="1650179405">

--- 结论 ---
hunter2 哈希 (1650179405) == HTML 中嵌入的哈希 (1650179405) ✓
wrongkey 哈希 (2695479675) != HTML 中嵌入的哈希 (1650179405) ✓
密钥原文 "hunter2" 不出现在 HTML 源码中 ✓
```

**总结**：黑客文章详情页门禁机制全部 9 项测试通过，验证结论如下：

1. **服务端渲染层面**：门禁 HTML 在 SSR 阶段就已生成，客户端禁用 JS 也无法绕过，黑客文章内容以 `display:none` 形式存在于 DOM 中
2. **客户端交互层面**：门禁通过 MutationObserver 监听 `hacker-mode` class 变化，动态切换显示/隐藏
3. **安全机制层面**：密钥采用 djb2 哈希本地验证，哈希值 `1650179405` 嵌入 HTML（`data-hash` 属性），密钥原文 `hunter2` 不出现在浏览器源码中
4. **隔离性层面**：普通文章不受门禁影响，两套文章库完全隔离
5. **覆盖性层面**：全部 15 篇黑客文章均正确应用门禁保护
