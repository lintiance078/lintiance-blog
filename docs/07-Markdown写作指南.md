## 1. 文章文件结构

每篇博客文章是一个 Markdown（`.md`）文件，由两部分组成：

1. **Frontmatter**（文件头部的 YAML 配置块）
2. **正文**（Markdown 格式的文章内容）

### 基本结构

```markdown
---
slug: "my-first-post"
title: "我的第一篇文章"
date: "2025-06-15"
tags: ["技术", "教程"]
summary: "这是一篇关于如何使用 Markdown 写作的指南"
cover: ""
cover_ascii: ""
word_count: 0
---

# 我的第一篇文章

> 在这里撰写文章正文...

## 第一节

正文内容...

## 第二节

更多内容...
```

### 文件存放位置

| 文章类型 | 存放目录 |
|----------|----------|
| 普通文章 | `src/content/posts/` |
| 黑客文章 | `src/content/hacker-posts/` |

### 文件命名

文件名格式为 `{slug}.md`，其中 `slug` 是 URL 友好的标识符。建议使用英文、小写、连字符分隔：

- 好的命名：`my-first-post.md`、`css-grid-layout.md`
- 不好的命名：`我的第一篇文章.md`、`My First Post.md`（中文或大写可能在 URL 中显示异常）

## 2. Frontmatter 配置详解

Frontmatter 是文章文件开头 `---` 包裹的 YAML 配置块，定义了文章的元数据。

### 字段说明

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| `slug` | 字符串 | 是 | URL 标识符，用于生成文章链接 | `"my-first-post"` |
| `title` | 字符串 | 是 | 文章标题，显示在页面和卡片中 | `"我的第一篇文章"` |
| `date` | 字符串 | 是 | 发布日期，格式 `YYYY-MM-DD` | `"2025-06-15"` |
| `tags` | 数组 | 否 | 文章标签，JSON 数组格式 | `["技术", "教程"]` |
| `summary` | 字符串 | 否 | 文章摘要，显示在卡片和列表页 | `"本文介绍了 Markdown 写作..."` |
| `cover` | 字符串 | 否 | 封面图路径 | `"/assets/images/cover.jpg"` |
| `cover_ascii` | 字符串 | 否 | ASCII 封面（替代图片封面） | （见第 6 节） |
| `word_count` | 数字 | 否 | 文章字数，用于显示阅读时间 | `1500` |

### 字段详细说明

#### slug（必填）

- 用于生成文章 URL：`/posts/{slug}`
- 建议使用英文小写，单词间用连字符 `-` 分隔
- 在同一目录下必须唯一，否则会覆盖同名文件
- 如果使用 TUI 工具发布文章，slug 会自动从标题生成

#### title（必填）

- 文章标题，显示在页面顶部和文章卡片中
- 支持中文、英文、特殊符号
- 建议控制在 50 字以内

#### date（必填）

- 发布日期，严格遵循 `YYYY-MM-DD` 格式
- 例如：`2025-06-15`、`2025-12-01`
- 日期用于文章排序，新文章在前
- 在时间轴布局中，日期决定文章在时间轴上的位置

> **注意**：日期格式必须正确，否则可能导致文章排序异常或构建报错。

#### tags（可选）

- 文章标签，格式为 JSON 数组
- 在 TUI 工具中使用 `#` 号分隔输入（详见第 3 节）
- 标签会显示在文章卡片和文章详情页
- 点击标签可以跳转到该标签的筛选页面

#### summary（可选）

- 文章摘要，显示在文章卡片中
- 建议控制在 100-200 字之间
- 如果留空，卡片中不显示摘要区域

#### cover（可选）

- 封面图路径，相对于 `public/` 目录
- 例如：`/assets/images/cover.jpg`
- 封面图会显示在文章卡片和文章详情页顶部
- 支持 JPG、PNG、WebP 格式
- 图片文件大小不能超过 25MB（Cloudflare Pages 限制）

#### cover_ascii（可选）

- ASCII 艺术字封面，替代图片封面
- 与 `cover` 字段互斥，如果同时设置，`cover` 优先
- 详细用法见第 6 节

#### word_count（可选）

- 文章字数，用于计算和显示阅读时间
- 阅读时间计算公式：`word_count / 300`（分钟），最少显示 1 分钟
- 如果使用 TUI 工具发布，系统会自动计算字数
- 如果手动创建文章，建议手动填写或留空

## 3. 标签格式规则

### 在 TUI 工具中输入标签

在 TUI 工具的「发布文章」流程中，标签使用 **`#` 号分隔**：

```
输入： #技术#安全#教程
生成： ["技术", "安全", "教程"]
```

### 连续 # 号规则

**`##` 视为两个独立标签的分隔符**：

```
输入： #前端##React
生成： ["前端", "React"]
```

这与单个 `#` 的效果相同，但更明确地表示这是两个独立的标签。

### 在 Frontmatter 中手动编辑标签

如果在 Markdown 文件中手动编辑标签，使用 JSON 数组格式：

```yaml
tags: ["技术", "安全", "教程"]
```

### 标签最佳实践

- 每个标签 2-8 个字符为佳
- 使用有意义的关键词，如 `前端`、`JavaScript`、`Docker`
- 每篇文章 2-5 个标签为宜
- 避免使用过于宽泛的标签（如 `技术`、`生活` 等太泛的主题）
- 标签区分大小写，建议统一使用一种格式

## 4. 代码块与语法高亮

### 代码块（Block Code）

代码块用于展示多行代码，使用三个反引号（`` ``` ``）包裹，并在开头的反引号后指定语言标签。语言标签决定了语法高亮的规则，使代码中的关键字、字符串、注释等元素以不同颜色显示，提升可读性。

**基本格式：**

````markdown
```javascript
function hello() {
  console.log("Hello, World!");
}
```

```python
def hello():
    print("Hello, World!")
```

```bash
npm run build
```
````

### 支持的语言标签

语法高亮基于 Prism.js，支持 200+ 种编程语言。以下是常用的语言标签：

| 语言 | 标签 | 备注 |
|------|------|------|
| JavaScript | `javascript`、`js` | 前端开发最常用 |
| TypeScript | `typescript`、`ts` | 带类型标注的 JS |
| Python | `python`、`py` | 脚本、数据分析 |
| HTML | `html` | 网页结构 |
| CSS | `css` | 样式表 |
| SCSS/Sass | `scss`、`sass` | CSS 预处理器 |
| Bash/Shell | `bash`、`shell`、`sh` | 终端命令 |
| PowerShell | `powershell`、`ps1` | Windows 终端 |
| JSON | `json` | 数据交换格式 |
| YAML | `yaml`、`yml` | 配置文件 |
| Markdown | `markdown`、`md` | 文档编写 |
| SQL | `sql` | 数据库查询 |
| Go | `go`、`golang` | Go 语言 |
| Rust | `rust`、`rs` | Rust 语言 |
| Java | `java` | Java 语言 |
| C | `c` | C 语言 |
| C++ | `cpp`、`c++` | C++ 语言 |
| C# | `csharp`、`cs` | C# 语言 |
| PHP | `php` | PHP 语言 |
| Ruby | `ruby`、`rb` | Ruby 语言 |
| Kotlin | `kotlin`、`kt` | Kotlin 语言 |
| Swift | `swift` | Swift 语言 |
| Dockerfile | `dockerfile`、`docker` | Docker 构建文件 |
| Nginx | `nginx` | Nginx 配置 |
| GraphQL | `graphql`、`gql` | GraphQL 查询 |
| 纯文本 | `text`、`plaintext` | 无语法高亮，仅等宽字体 |

> **提示**：如果不确定某个语言是否支持，可以尝试不带语言标签（或使用 `text` / `plaintext`），代码块会以纯文本形式显示，无语法高亮但保留等宽字体格式。

### 行内代码（Inline Code）

行内代码使用**单个反引号**（`` ` ``）包裹，适用于在段落中引用变量名、函数名、命令或短代码片段。行内代码不会触发语法高亮，但会使用等宽字体和浅色背景以区别于正文。

```markdown
使用 `npm install` 安装依赖。

在 `config.yaml` 中设置 `port: 3000` 参数。

调用 `console.log()` 输出调试信息。
```

**行内代码 vs 代码块对比：**

| 特性 | 行内代码 | 代码块 |
|------|----------|--------|
| 语法 | 单个反引号 `` ` `` | 三个反引号 `` ``` `` |
| 用途 | 短代码片段、命令、变量名 | 多行代码、完整程序 |
| 语法高亮 | 不支持 | 支持（通过语言标签） |
| 换行 | 不支持 | 支持 |
| 显示位置 | 段落内，与文字同行 | 独立段落，独占一区 |

### ASCII 字符画在代码块中

如果需要展示 ASCII 字符画或纯文本图表，建议使用 `text` 或 `plaintext` 语言标签（或直接省略语言标签），这样可以避免语法高亮系统误判字符画中的特殊符号，同时保留等宽字体对齐效果：

````markdown
```text
    /\___/\
   (  o o  )
   (  =^=  )
    (______)

  ASCII Cat ^_^
```
````

渲染效果：

```text
    /\___/\
   (  o o  )
   (  =^=  )
    (______)

  ASCII Cat ^_^
```

> **注意**：如果使用 `javascript`、`python` 等标签包裹 ASCII 字符画，语法高亮器会尝试解析其中的字符，可能导致颜色混乱或对齐异常。始终使用 `text` 或 `plaintext` 标签展示 ASCII 字符画。

### 代码块渲染说明

代码块在 Markdown 正文中编写后，经过 Astro 构建流程渲染为带语法高亮的 HTML 代码块。渲染过程如下：

1. **Markdown 解析**：Astro 将 Markdown 文件中的代码块（三个反引号包裹的内容）解析为 HTML `<pre><code>` 结构
2. **语法高亮**：基于 Prism.js 语法高亮引擎，根据代码块指定的语言标签，对代码中的关键字、字符串、注释、函数名等元素进行着色
3. **样式注入**：注入博客主题的代码块 CSS 样式，包括背景色、字体、边框等

代码块在页面上的最终渲染效果具有以下特点：

- **深色背景**：使用深色底色（`#1e293b`），模拟终端窗口风格
- **等宽字体**：使用 JetBrains Mono、Fira Code、Cascadia Code 等编程字体，确保字符对齐
- **语法高亮**：关键字、字符串、注释、函数名、运算符等以不同颜色区分，大幅提升代码可读性
- **语言标签显示**：代码块顶部显示语言名称（如 `JavaScript`、`Python`），方便读者快速识别代码类型
- **复制按钮**：鼠标悬停在代码块上时，右上角出现复制按钮，点击即可一键复制全部代码
- **横向滚动**：代码行过长时自动出现横向滚动条，避免换行破坏代码格式

在黑客模式下，代码块会进一步适配为黑客终端风格（绿色文字、黑色背景、扫描线效果）。

## 5. 链接处理

### 链接的基本写法

在 Markdown 中创建链接的标准语法是 `[链接文字](URL)`：

```markdown
[GitHub](https://github.com)
[项目文档](/docs/guide)
[返回首页](/)
```

- `[链接文字]`：读者看到的可点击文字
- `(URL)`：点击后跳转的目标地址，可以是绝对 URL（`https://...`）或相对路径（`/...`）

### 自动识别外部网址链接

在正文中直接书写裸 URL（bare URL），系统会**自动识别**并将其转换为可点击的链接，无需手动添加 Markdown 链接语法。这项功能让写作更加流畅，你可以直接粘贴网址，系统会自动处理链接渲染。

**自动识别的 URL 格式**：
- 以 `http://` 开头的 URL
- 以 `https://` 开头的 URL

```markdown
访问 https://github.com 了解更多。

更多信息请参考 https://developer.mozilla.org/zh-CN/docs/Web/JavaScript。
```

渲染效果：访问 https://github.com 了解更多。

系统会自动检测以 `http://` 或 `https://` 开头的 URL 字符串，并将其渲染为可点击的超链接。**裸 URL 链接与手动创建的 `[文字](URL)` 链接在安全行为上完全一致**——点击时都会触发外部链接安全弹窗（详见下方「外部链接安全弹窗」小节及第 9 节）。

> **注意**：不以 `http://` 或 `https://` 开头的文本（如 `www.example.com` 或 `example.com`）**不会**被自动识别为链接。如需将其作为链接，请使用 `[文字](https://...)` 格式手动创建。

### 内部链接（本站链接）

指向本站其他页面的链接属于内部链接。与外部链接不同，内部链接**不会触发安全弹窗**，点击后直接导航，用户体验更加流畅。

**内部链接的判别规则**：

以下类型的链接均视为内部链接，不会弹出安全确认对话框：

- **相对路径链接**（以 `/` 开头）：如 `/articles`、`/tags`、`/posts/my-post`
- **锚点链接**（以 `#` 开头）：如 `#section-1`、`#top`
- **本站完整域名链接**：与当前页面同域名的链接（例如 `https://lintiance-blog.pages.dev/posts/xxx`）
- **非 HTTP(S) 协议链接**：如 `mailto:example@example.com`、`tel:+8613800000000`

```markdown
[查看所有文章](/articles)
[返回首页](/)
[查看标签](/tags)
[跳转到第一节](#1-文章文件结构)
```

**内部链接 vs 外部链接判别逻辑**：

| 链接类型 | 示例 | 是否弹窗 |
|----------|------|----------|
| 相对路径（`/` 开头） | `/articles`、`/tags` | 否，直接导航 |
| 锚点（`#` 开头） | `#section-1` | 否，直接跳转 |
| 本站域名 | `https://lintiance-blog.pages.dev/posts/xxx` | 否，直接导航 |
| 外部域名（http/https） | `https://github.com` | 是，弹出安全弹窗 |
| 邮件/电话协议 | `mailto:test@test.com` | 否，直接调用系统程序 |

> **提示**：使用相对路径（以 `/` 开头）创建内部链接是最推荐的方式，因为无论博客部署在哪个域名下，相对路径链接都能正确工作，且不会触发安全弹窗。

### 外部链接安全弹窗

指向外部域名的链接（即域名与本站不同的 `http://` 或 `https://` 链接）属于外部链接。点击外部链接时，**系统会弹出模态安全确认对话框**，提示用户即将离开本站：

```
┌─────────────────────────────────────────┐
│  ⚠️ 您即将离开本站                       │
│                                         │
│  请注意甄别外部网站的安全风险              │
│                                         │
│  目标链接：https://example.com           │
│                                         │
│         [取消]      [继续访问]            │
└─────────────────────────────────────────┘
```

**弹窗行为说明**：
- 弹窗会明确显示**目标 URL**，让用户在跳转前确认链接地址，防止钓鱼链接伪装
- 点击「取消」：关闭弹窗，**不跳转**，留在当前页面
- 点击「继续访问」：在**新标签页**中打开外部链接，当前页面保持不变
- 弹窗采用模态设计，必须做出选择后才能继续操作

**不触发弹窗的情况**：
- 以 `/` 开头的相对路径链接（如 `/articles`、`/tags`）
- 指向本站域名的链接（同源链接）
- 锚点链接（如 `#section-1`）

> **详细说明**：关于外部链接安全弹窗的工作原理、设计目的、实现细节和测试方法，请参见本文档第 9 节「外部链接安全弹窗说明」。

### 外部链接最佳实践

为了提高文章的可信度和安全性，建议遵循以下实践：

1. **优先使用文字链接**：避免直接粘贴裸 URL，使用 `[描述文字](URL)` 形式让读者了解链接内容
   ```markdown
   <!-- 推荐 -->
   请参考 [MDN 官方文档](https://developer.mozilla.org/zh-CN/)

   <!-- 不推荐 -->
   请参考 https://developer.mozilla.org/zh-CN/
   ```

2. **链接文字应具有描述性**：避免使用「点击这里」「链接」等模糊描述
   ```markdown
   <!-- 推荐 -->
   查看 [React 官方入门教程](https://react.dev/learn)

   <!-- 不推荐 -->
   [点击这里](https://react.dev/learn) 查看教程
   ```

3. **注明链接来源**：在引用外部资料时，简要说明链接来源的可信度
   ```markdown
   > 参考 [OWASP Top 10 安全风险](https://owasp.org/www-project-top-ten/)（权威安全组织）
   ```

4. **检查链接有效性**：发布前确认所有外部链接均可正常访问，避免死链

5. **优先使用 HTTPS**：确保外部链接使用 `https://` 协议，保证传输安全

### 链接行为总结

| 链接类型 | 示例 | 行为 |
|----------|------|------|
| 内部链接（相对路径） | `/articles`、`/tags` | 直接导航，无弹窗 |
| 内部链接（锚点） | `#section-1` | 直接跳转，无弹窗 |
| 外部链接（手动创建） | `[GitHub](https://github.com)` | 弹出安全确认弹窗 |
| 外部链接（裸 URL） | `https://github.com` | 弹出安全确认弹窗 |
| 外部链接（新标签） | 所有外部链接 | 确认后在新标签页打开 |

## 6. ASCII 字符画

### 什么是 ASCII 字符画

ASCII 字符画是使用文字字符绘制的图案，在博客中渲染为等宽字体的终端风格显示。

### 两种使用方式

#### 方式一：作为文章封面（cover_ascii）

在 frontmatter 中设置 `cover_ascii` 字段：

```yaml
---
title: "我的文章"
cover_ascii: |
  ╔══════════════════════════════════╗
  ║     WELCOME TO MY BLOG          ║
  ╚══════════════════════════════════╝
---
```

> **注意**：`cover_ascii` 和 `cover` 字段互斥。如果同时设置，`cover`（图片封面）优先。

#### 方式二：在正文中内嵌

在 Markdown 正文中直接使用 `<pre class="ascii-art">` 标签：

```markdown
## 以下是 ASCII 字符画

<pre class="ascii-art">
    /\___/\
   (  o o  )
   (  =^=  )
    (______)
</pre>
```

### ASCII 字符画样式

- 字体：等宽字体（JetBrains Mono、Fira Code、Cascadia Code 等）
- 字号：`0.45rem`（适配字符对齐）

## 9. 外部链接安全弹窗说明

### 功能概述

外部链接安全弹窗是博客内置的客户端安全防护功能，旨在保护读者免受钓鱼链接、恶意网站等网络安全威胁。当读者点击文章中的外部链接时，系统会先弹出确认对话框，由读者自行判断是否继续访问。

### 设计目的

在网络环境中，攻击者可能会在文章评论区或通过其他方式植入恶意链接。即使作者本人无意中引用了不可信的外部资源，安全弹窗也能为读者提供一道额外的防线：

- **防止钓鱼攻击**：弹窗中完整显示目标 URL，读者可以检查域名是否可疑
- **防止恶意跳转**：避免点击后直接被重定向到恶意网站
- **增强安全意识**：提醒读者正在离开本站，注意甄别外部网站风险

### 工作原理

安全弹窗通过客户端 JavaScript 实现，具体流程如下：

1. **事件拦截**：JavaScript 监听页面上所有链接的点击事件
2. **链接分类**：判断链接目标是内部链接还是外部链接
   - 内部链接（本站域名、相对路径 `/`、锚点 `#`）：直接放行，不拦截
   - 外部链接（不同域名的 `http://` 或 `https://` 链接）：拦截点击，进入下一步
3. **弹窗确认**：弹出确认对话框，显示完整的目标 URL
4. **用户决策**：
   - 点击「取消」→ 关闭弹窗，不跳转
   - 点击「继续访问」→ 在新标签页中打开目标链接

### 弹窗内容

安全弹窗的提示文案如下：

```
您即将离开本站，访问外部链接：
https://example.com
是否继续？

        [取消]    [继续访问]
```

- 弹窗中会原样显示目标 URL，方便读者核实链接的真实性
- 如果链接是裸 URL（bare URL），弹窗中的 URL 与原文一致
- 如果链接是 Markdown 格式 `[文字](URL)`，弹窗中显示的是 `(URL)` 中的真实地址

### 不受影响的链接类型

以下类型的链接**不会**触发安全弹窗，点击后直接生效：

| 链接类型 | 示例 | 说明 |
|----------|------|------|
| 本站相对路径 | `/articles`、`/tags`、`/posts/my-post` | 以 `/` 开头，指向本站其他页面 |
| 锚点链接 | `#section-1`、`#top` | 页面内跳转 |
| 本站完整 URL | `https://lintiance-blog.pages.dev/posts/xxx` | 与当前域名相同 |
| 邮件链接 | `mailto:example@example.com` | 协议非 http/https |
| 电话链接 | `tel:+8613800000000` | 协议非 http/https |

### 如何测试

如果你想验证安全弹窗功能是否正常工作，可以通过以下步骤测试：

1. 打开任意一篇已发布的文章
2. 找到文章中的外部链接（例如指向 GitHub、MDN 等外部网站的链接）
3. 点击该链接
4. 确认弹窗是否正常弹出，显示正确的目标 URL
5. 点击「取消」验证是否留在当前页面
6. 再次点击链接，选择「继续访问」验证是否在新标签页中打开目标链接

### 注意事项

- **客户端功能**：安全弹窗是纯客户端（浏览器端）功能，不会影响 SEO。搜索引擎爬虫在抓取页面时不会触发 JavaScript 弹窗，因此搜索引擎可以正常解析和跟踪所有链接
- **不影响 Markdown 渲染**：弹窗逻辑在 Markdown 渲染为 HTML 之后执行，不会改变文章内容或链接结构
- **新标签页打开**：确认后外部链接始终在新标签页中打开（`target="_blank"`），不会覆盖当前页面
- **用户选择权**：弹窗只是提供提醒，最终是否访问由用户自行决定，博客不会阻止用户访问任何合法外部链接
