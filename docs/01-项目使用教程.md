## 1. 项目功能概览

林天策 Blog 是一个基于 Astro 框架构建的个人博客系统，部署在 Cloudflare Pages 上，具备以下核心功能：

### 前端功能

| 功能 | 说明 |
|------|------|
| **5 种文章布局** | Masonry 瀑布流、Grid 均等网格、List 纯列表、Card-List 混合、Timeline 时间轴 |
| **5 种导航交互** | 静态导航、Sticky 固定置顶、下滑隐藏/上滑显示、滚动透明渐变、滚动收缩 |
| **4 种卡片风格** | 圆角阴影悬浮、简约无边框、封面图置顶、背景虚化封面 |
| **主题切换** | 浅色/深色主题一键切换 |
| **简约模式** | 关闭全部装饰特效，使用朴素样式，提升低配设备浏览速度 |
| **毛玻璃效果** | 可开关，支持低/中/高三级模糊强度 |
| **页面动效** | 可开关，支持淡入淡出/滑动推入/缩放/翻转四种模式，可调节动画时长 |
| **侧边栏组件** | 常驻侧边栏、抽屉侧边面板、文章悬浮TOC、标签云，均可独立开关 |
| **隐秘黑客模式** | 通过特殊流程触发，切换到复古终端风格，显示独立黑客内容库 |
| **站点健康检测** | 实时显示站点状态信息 |
| **Pagefind 全文搜索** | 构建后生成静态搜索索引，无需后端 |
| **本地收藏** | 基于 localStorage 的文章收藏，无需登录 |

### 后台管理（TUI 终端工具）

| 功能 | 说明 |
|------|------|
| **双入口模式** | 普通版/黑客版分别管理各自文章库 |
| **站点管理** | 网站名称、描述、风格、黑客密钥配置 |
| **文章管理** | 新建、编辑、删除、隐藏/显示、迁移（普通<->黑客） |
| **一键部署** | 自检 → 构建 → Git 推送 → 自动触发 Cloudflare Pages 部署 |

### 一键脚本

| 脚本 | 说明 |
|------|------|
| 01_check_project.bat | 项目完整性自检 |
| 02_push_github.bat | 一键提交到 GitHub |
| 03_deploy_cloudflare.bat | 一键触发 Cloudflare 部署 |
| 04_start_dev.bat / stop_dev.bat | 本地开发服务启停 |
| 05_start_tui.bat / stop_tui.bat | TUI 工具启停 |

## 2. 环境安装

### 系统要求

- **操作系统**：Windows 10/11（TUI 工具和批处理脚本仅支持 Windows）
- **Node.js**：v18 或更高版本（[下载地址](https://nodejs.org/)）
- **Git**：最新版本（[下载地址](https://git-scm.com/download/win)）
- **Cloudflare 账号**：用于部署、D1 数据库和 KV 存储服务

### 安装步骤

```bash
# 1. 克隆项目（或解压项目文件到本地）
git clone <你的仓库地址> lintiance-blog
cd lintiance-blog

# 2. 安装项目依赖
npm install

# 3. 验证安装
npx astro --version
```

> **重要**：`npm install` 必须成功完成，否则后续所有步骤都无法进行。如果安装失败，请检查网络连接，或尝试切换 npm 镜像源。

## 3. 本地开发

### 方式一：使用一键脚本（推荐）

双击 `oneclick_scripts\04_本地开发服务\start_dev.bat`，脚本会自动：
1. 检查 Node.js 环境
2. 检查并安装依赖（如未安装）
3. 启动 Astro 开发服务器

### 方式二：命令行

```bash
# 启动开发服务器（支持热重载）
npm run dev
```

### 访问网站

启动后，在浏览器中打开以下地址：

```
http://localhost:4321
```

开发服务器特性：
- 文件修改后自动刷新页面
- 支持所有 Astro 页面和组件
- 开发模式下搜索功能需要先执行 `npm run build` 才可用

### 停止服务

若要停止开发服务器：
- 在命令行窗口按 `Ctrl+C`
- 或双击 `oneclick_scripts\04_本地开发服务\stop_dev.bat`

## 4. 生产构建

```bash
# 执行生产构建
npm run build
```

构建流程：
1. **构建自检**（`scripts/build-check.js`）：检查目录结构、Pagefind、wrangler 配置、图片大小
2. **Astro 构建**：生成静态 HTML 到 `dist/` 目录
3. **Pagefind 索引**：生成搜索索引到 `dist/pagefind/`

### Cloudflare Pages 硬性限制

| 限制项 | 上限 | 说明 |
|--------|------|------|
| 单文件大小 | 25 MB | `dist/` 内单个文件不能超过 25MB |
| 总文件数 | 20,000 | `dist/` 全部文件总数上限 |

构建自检脚本会自动检查图片大小，超过 25MB 会报错**终止构建**。

## 6. 新增文章流程

### 方式一：使用 TUI 工具（推荐）

```bash
npm run tui
```

在 TUI 主菜单中：
1. 选择双入口模式（普通版 / 黑客版）
2. 选择 `② 文章管理` → `2) 发布文章`
3. 按表单提示依次输入：标题 → 标签 → 作者 → 头像 → 发布时间 → 摘要 → 正文
4. 系统自动生成 `.md` 文件并保存到对应目录

> 详细操作请参考 [TUI 使用教程](./02-TUI使用教程.md)

### 方式二：手动创建

1. 在 `src/content/posts/`（普通文章）或 `src/content/hacker-posts/`（黑客文章）目录下创建 `.md` 文件
2. 文件头部添加 frontmatter：

```yaml
---
slug: "my-new-post"
title: "我的新文章"
date: "2025-06-15"
tags: ["技术", "教程"]
summary: "文章摘要描述"
cover: ""
cover_ascii: ""
word_count: 0
---
```

3. 正文使用 Markdown 语法编写

> 详细写作规范请参考 [Markdown 写作指南](./07-Markdown写作指南.md)

| 限制项 | 上限 | 说明 |
|--------|------|------|

## 8. ASCII 字符画网页渲染说明

### 渲染机制

ASCII 字符画使用 `<pre class="ascii-art">` 标签渲染：

```html
<pre class="ascii-art">
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@@@@@@@@@@@@@@@@@@@@@@@@@@@@%#*+=-:...  ..::-=+*#%@@@@@@@@@@
</pre>
```

### CSS 样式

- 等宽字体：`JetBrains Mono`, `Fira Code`, `Cascadia Code`, Consolas
- 字号：`0.45rem`（可根据需要调整）
- 行高：`1.15`（紧凑排列）
- 深色背景：`#1e293b`（模拟终端效果）

### 在文章中使用

有两种方式使用 ASCII 字符画：

**方式一：文章封面（frontmatter）**

在 `cover_ascii` 字段中填入 ASCII 文本，会在文章顶部显示为 ASCII 封面。

**方式二：正文内嵌**

在 Markdown 正文中直接使用 `<pre class="ascii-art">` 标签：

```markdown
## 我的 ASCII 字符画

<pre class="ascii-art">
（ASCII 文本内容）
</pre>
```

## 9. 构建自检说明

`npm run build` 执行前会自动运行 `scripts/build-check.js`：

| 检查项 | 级别 | 说明 |
|--------|------|------|
| 目录结构完整性 | 错误 | `src/pages`、`src/layouts` 等必须存在 |
| Pagefind 可用性 | 警告 | 未安装时搜索功能不可用 |
| `wrangler.toml` 配置 | 警告 | 占位符提示 |
| 图片文件大小 | 错误 | 超过 25MB 终止构建 |
| 图片数量 | 警告 | 接近 20,000 时提示 |

**自检不通过 → 构建终止，不会生成损坏的 dist 产物。**

## 10. 一键流水线功能说明

一键流水线在 TUI 工具中执行，完整流程：

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 系统自检  │ ──▶ │ 本地构建  │ ──▶ │ Git 推送  │
└──────────┘     └──────────┘     └──────────┘
   失败终止          失败终止          成功！
```

### 操作步骤

1. 启动 TUI：`npm run tui`
2. 选择双入口模式（普通版 / 黑客版）
3. 选择 `③ 部署（推送 GitHub → Cloudflare Pages）`
4. 输入提交信息（或直接回车使用默认信息）
5. 等待执行完成

### 执行逻辑

- **自检不通过** → 直接终止，不构建、不推送
- **构建失败** → 终止，输出错误日志
- **构建成功** → 执行 `git add` → `git commit` → `git push`
- **推送成功** → GitHub 自动触发 Cloudflare Pages 部署

### 注意事项

- Cloudflare Pages 需要提前在后台绑定 GitHub 仓库
- 流水线不调用 Cloudflare 部署 API
- 推送后等待 1-3 分钟，Cloudflare Pages 自动完成部署
- 部署验证建议：等待 2-5 分钟后访问 Cloudflare Pages 控制台检查构建状态
