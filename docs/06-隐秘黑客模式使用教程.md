## 1. 什么是黑客模式

隐秘黑客模式是林天策 Blog 的一个隐藏功能，它将博客切换为**老式复古黑客终端风格**，并显示一套**独立的内容库**（黑客文章）。

### 黑客模式的特点

- **视觉风格**：黑底绿字、等宽字体、微弱扫描线效果，模拟老式 CRT 终端
- **独立内容**：黑客文章与普通文章完全分离，存放在 `src/content/hacker-posts/` 目录
- **隐秘触发**：普通访客无法发现此模式，需要通过特定流程激活
- **密钥保护**：需要输入正确的密钥才能进入，密钥通过哈希比对验证
- **不留痕迹**：刷新页面即退出黑客模式，不会在任何地方持久化

## 2. 触发流程详解

进入黑客模式需要按照以下步骤操作，**缺一不可**。

### 第 1 步：打开设置面板

点击网站右上角的 **齿轮图标（⚙️）**，打开设置面板。

> **提示**：健康检查功能已从右下角浮动球迁移至设置面板中。如需查看站点健康状态，请打开设置面板查看。

### 第 2 步：连续点击站点名称 5 次

在设置面板的最底部「站点信息」区域，找到**站点名称**（默认显示为"林天策 Blog"）。

**快速连续点击站点名称 5 次**，必须在 **2 秒内**完成。如果超时，计数会归零，需要重新点击。

> **提示**：站点名称区域在设置面板中没有特殊的视觉提示，它看起来就是一个普通的文字标签。这是设计如此——保持隐秘性。

### 第 3 步：观察像素 loading 标识

成功触发后，以下变化会发生：

1. **首页右下角**会出现一个像素风格的 loading 标识：
   ```
   ▮▯▮▯▮
   ```
   这个标识呈青绿色（`#00ff41`），带有像素闪烁动画，字体为等宽字体。

   > **显示范围**：该像素 loading 标记**仅在首页右下角显示**。文章详情页、标签页、设置面板等其他页面不会显示该标记。
   >
   > **标记样式**：固定定位（`position: fixed`）于页面右下角，绿色像素字体，带有 CSS 闪烁动画（`animation: blink`），z-index 较高以确保始终可见。

2. 搜索框的占位符文字会从"输入关键词，按回车搜索..."变为：
   ```
   输入密钥...
   ```

3. 此时在搜索框中输入密钥也可直接触发黑客模式（无需再次点击站点名称）。

### 第 4 步：打开搜索框

按 **Ctrl+K**（或点击右上角的搜索图标 🔍）打开搜索弹窗。

### 第 5 步：在搜索框中输入密钥

在搜索框中输入**黑客模式访问密钥**，然后按 **Enter** 键。

- 如果密钥正确：页面会切换到黑客终端风格
- 如果密钥错误：执行正常的文章搜索

### 第 6 步：确认切换成功

切换成功后：
- 页面背景变为黑色，文字变为青绿色
- 所有 UI 元素（导航栏、卡片、按钮等）变为终端风格
- 普通文章被隐藏，只显示黑客文章
- 文章计数更新为黑客文章数量

## 3. 密钥配置与管理

### 密钥存储位置

黑客模式密钥存储在**两个位置**：

| 位置 | 用途 | 说明 |
|------|------|------|
| `.env` 文件 | 本地开发 | 开发时 Vite 构建注入 |
| `wrangler.toml` 的 `[vars]` | 生产部署 | Cloudflare Pages 构建时注入 |

两个位置的密钥必须保持一致。

### 密钥配置概览

黑客模式密钥的配置流程总结如下：

1. **配置位置**：密钥在 `.env` 和 `wrangler.toml` 两个文件中配置，两处必须保持一致。
2. **获取密钥**：通过 TUI 工具（推荐）或手动编辑配置文件的方式设置密钥，具体步骤见下方「密钥获取与填写步骤」。
3. **密钥修改后需要重新构建部署**：修改密钥后，必须执行以下流程才能使新密钥在线上生效：

   ```bash
   npm run build          # 重新构建，生成包含新密钥哈希的静态文件
   git add .env wrangler.toml
   git commit -m "更新密钥"
   git push               # 推送到 GitHub，触发 Cloudflare Pages 自动部署
   ```

   推送后，Cloudflare Pages 会自动检测到仓库更新并触发部署，部署完成后新密钥立即生效。

#### 第三步：手动配置（备用方法）

如果你无法使用 TUI 工具，也可以手动编辑配置文件。

##### 3.1 编辑 .env 文件

`.env` 文件位于**项目根目录**（即 `lintiance-blog/` 文件夹下）。如果文件不存在，请新建一个。

用记事本（Notepad）或任意文本编辑器打开 `.env` 文件，添加或修改以下行：

```env
HACKER_SECRET_KEY=你的密钥
```

例如，如果你的密钥是 `MyBlog2024!`，则写入：

```env
HACKER_SECRET_KEY=MyBlog2024!
```

> **注意**：`.env` 文件中密钥**不需要加引号**，直接写等号后面的值即可。

##### 3.2 编辑 wrangler.toml 文件

`wrangler.toml` 同样位于项目根目录。用文本编辑器打开，找到 `[vars]` 部分（如果不存在则添加），在其中添加或修改 `HACKER_SECRET_KEY`：

```toml
[vars]
HACKER_SECRET_KEY = "MyBlog2024!"
```

> **注意**：`wrangler.toml` 中密钥**需要加引号**（双引号），与 `.env` 文件的格式不同。

##### 3.3 验证配置

配置完成后，两个文件的内容应如下所示：

`.env` 文件：
```
HACKER_SECRET_KEY=MyBlog2024!
```

`wrangler.toml` 文件（`[vars]` 部分）：
```toml
[vars]
HACKER_SECRET_KEY = "MyBlog2024!"
```

两个文件中的密钥值必须一致。

### 密钥修改后生效流程

修改密钥后，**必须重新构建部署**才能让新密钥在线上生效。以下是完整流程：

#### 1. 本地构建

在项目根目录运行：

```bash
npm run build
```

构建过程会使用 djb2 算法对密钥进行哈希处理，并将哈希值嵌入到生成的 HTML 文件中。构建成功后会输出类似以下信息：

```
✓ Building completed in 12.34s
```

#### 2. 推送到 GitHub

将修改后的文件提交并推送到 GitHub 仓库：

```bash
git add .env wrangler.toml
git commit -m "更新黑客模式密钥"
git push
```

#### 3. 等待 Cloudflare Pages 部署

推送后，Cloudflare Pages 会自动检测到仓库更新并触发部署。部署过程通常需要 **1-3 分钟**。

你可以在 Cloudflare Dashboard 的 Pages 项目页面查看部署进度：

```
Pages → 你的项目 → 部署 → 查看当前部署状态
```

部署状态会依次显示：
- `Building...`（正在构建）
- `Deploying...`（正在部署）
- `Active`（部署完成）

#### 4. 验证新密钥是否生效

部署完成后，打开你的博客网站，按照以下步骤验证：

1. 打开设置面板（点击右上角齿轮图标）
2. 连续点击站点名称 5 次，确认出现 `▮▯▮▯▮` 像素标识
3. 按 Ctrl+K 打开搜索框
4. 输入**新密钥**，按回车
5. 如果页面切换为黑客终端风格，说明新密钥已生效

你也可以通过浏览器开发者工具验证：按 F12 打开开发者工具，在 Elements 面板中查看 `<html>` 标签，应能看到 `data-hacker-hash` 属性，其值为新密钥的 djb2 哈希值。

> **提示**：可以参考 `docs/测试用例-黑客文章门禁验证.md` 文件中的测试用例来完整验证门禁功能是否正常工作。

### 如何修改密钥

如果你已配置过密钥，需要更换新密钥，可以使用以下任一方式。

**方式一：使用 TUI 工具（推荐）**

1. 启动 TUI：`npm run tui`
2. 选择「黑客版」模式
3. 进入 `① 站点管理` → `3) 隐秘模式访问密钥设置`
4. 输入新密钥 → 确认密钥 → 密钥自动写入 `.env` 和 `wrangler.toml`

**方式二：手动修改**

1. 编辑项目根目录的 `.env` 文件，修改 `HACKER_SECRET_KEY` 的值
2. 编辑 `wrangler.toml`，修改 `[vars]` 部分的 `HACKER_SECRET_KEY` 的值
3. 重新构建部署



**方式三：Cloudflare 后台**

1. 登录 Cloudflare Dashboard
2. 进入 Pages 项目 → `设置` → `环境变量`
3. 添加/修改 `HACKER_SECRET_KEY` 变量

> **重要**：修改密钥后**必须重新构建部署**才能生效。详见上方「密钥修改后生效流程」。

### 密钥安全建议

- 使用至少 **8 位**以上的密钥
- 包含大小写字母和数字
- **不要使用** `hunter2`、`password`、`12345678` 等常见密码
- 不要使用与个人信息相关的词语（如生日、姓名等）

## 4. 密钥安全机制

### 哈希比对，密钥原文不出现在浏览器

黑客模式采用以下安全机制保护密钥：

1. **构建时哈希**：在构建阶段，使用 **djb2 哈希算法**对密钥进行哈希处理。哈希计算在 `npm run build` 时由 Vite 构建流程自动执行，密钥原文仅在构建时存在于服务器内存中，构建完成后不会保留在任何产物文件中。
2. **哈希值嵌入 HTML 作为 data 属性**：构建完成后，密钥的 djb2 哈希值被嵌入到生成的 HTML 文件的 `<html>` 标签上，作为 `data-hacker-hash` 属性。例如：`<html lang="zh-CN" data-hacker-hash="1234567890">`。前端验证时会读取该属性值进行比对。
3. **仅存储哈希值**：前端代码中只包含密钥的哈希值（一个数字），**密钥原文不会出现在任何浏览器源码中**。无论你在浏览器开发者工具中如何搜索，都无法找到密钥原文——只能看到哈希值。
4. **前端本地比对**：用户输入密钥后，前端对输入进行同样的 djb2 哈希计算，然后与 `data-hacker-hash` 属性中的哈希值比对，比对通过即允许进入黑客模式。
5. **不发起网络请求**：密钥验证完全在浏览器本地完成，不会向服务器发送密钥原文。整个验证过程不涉及任何网络通信。
6. **每次部署自动更新哈希**：每次运行 `npm run build` 并部署后，HTML 中嵌入的都是**当前密钥的哈希值**。如果你修改了密钥并重新部署，旧的哈希值会被新哈希值完全替换，旧密钥立即失效。

### 你可以验证

在浏览器中打开开发者工具（F12），在 Elements 面板中查看 `<html>` 标签，你会看到 `data-hacker-hash` 属性，其值为当前密钥的 djb2 哈希值。你也可以在页面源代码中搜索 `HACKER_SECRET_KEY`，你**不会找到密钥原文**——只会找到一个哈希值数字。

> **技术细节**：密钥哈希值在构建时通过 Vite 的环境变量注入机制嵌入到前端代码中。具体来说，构建脚本通过 `import.meta.env.HACKER_SECRET_KEY` 读取密钥原文，使用 djb2 算法计算哈希值，然后将哈希值存储在页面中的一个隐藏 `<span>` 元素（`#hacker-key-hash`）中。前端验证时，JavaScript 代码读取该隐藏元素的文本内容来获取哈希值，与用户输入进行比对。密钥原文从不出现在任何构建产物中。

### 安全边界

| 安全层面 | 说明 |
|----------|------|
| 浏览器源码 | 密钥原文不会出现 |
| 网络请求 | 验证不发起网络请求 |
| 服务器端 | 构建时注入，运行时不可见 |
| 代码仓库 | `.env` 文件已在 `.gitignore` 中排除 |

> **注意**：djb2 是一个简单的哈希算法，不是密码学安全的哈希函数。此机制的目的是防止普通访客通过查看源码发现密钥，而不是防御专业的密码破解。请保持密钥的保密性。

## 5. 密钥配置

本节提供密钥配置的核心要点速览，详细步骤请参考上方「密钥配置与管理」章节。

### 密钥存储

密钥存储在项目根目录 `.env` 文件中，变量名为 `HACKER_SECRET_KEY`：

```env
HACKER_SECRET_KEY=你的密钥
```

### 修改密钥后的生效流程

修改密钥后，必须重新构建和部署才能让新密钥在线上生效。完整流程如下：

```bash
npm run build          # 1. 重新构建，生成包含新密钥哈希的静态文件
git push               # 2. 推送到 GitHub，触发 Cloudflare Pages 自动部署
```

推送后 Cloudflare Pages 会自动检测仓库更新并触发部署（通常 1-3 分钟），部署完成后新密钥立即生效。

### 密钥验证机制

密钥使用 **djb2 哈希算法**进行比对验证：
- 构建时将密钥的 djb2 哈希值嵌入 HTML 的 `data-hacker-hash` 属性中
- 用户输入密钥后，前端对输入进行同样的 djb2 哈希计算
- 比对哈希值，通过则允许进入黑客模式
- **密钥原文不在前端明文存储**，浏览器源码中仅包含哈希值

## 6. 会话规则

### 刷新页面 = 退出黑客模式

黑客模式**不会持久化**到任何存储中。以下操作都会导致退出黑客模式：

- 刷新页面（F5 或 Ctrl+R）
- 关闭浏览器标签页后重新打开
- 从其他页面导航回来（浏览器后退/前进）
- 手动清除浏览器数据

### 设计原因

不持久化是**有意设计**，目的是：
- 保持隐秘性：黑客模式不会留下明显的使用痕迹
- 安全性：没有人可以在你离开后直接访问黑客内容
- 简洁性：每次进入都是全新的触发流程

### 如何重新进入

每次需要查看黑客内容时，都需要重新执行完整的触发流程（第 2 节的 6 个步骤）。

## 7. 视觉风格说明

进入黑客模式后，整个网站的视觉风格会发生以下变化：

### 配色方案

| 元素 | 颜色 | 说明 |
|------|------|------|
| 背景 | `#0a0a0a`（纯黑） | 终端背景色 |
| 主文字 | `#00ff41`（青绿） | 类似老式终端荧光屏 |
| 次要文字 | `#008f11`（暗绿） | 辅助信息文字 |
| 高亮文字 | `#00ff88`（亮绿） | 标题等重要文字 |

## 8. 文章内容说明

### 普通文章与黑客文章

博客有两套完全独立的文章库：

| 类型 | 存放目录 | 访问方式 | 示例 |
|------|----------|----------|------|
| 普通文章 | `src/content/posts/` | 所有访客可见 | 技术教程、生活随笔等 |
| 黑客文章 | `src/content/hacker-posts/` | 仅黑客模式可见 | 安全技术、CTF 题解等 |

### 进入黑客模式后

- 普通文章被**隐藏**（`display: none`）
- 黑客文章**显示**出来
- 文章计数更新为黑客文章数量
- 搜索功能仅搜索黑客文章

### 退出黑客模式后

- 黑客文章被**隐藏**
- 普通文章**恢复显示**
- 一切恢复正常状态

### 黑客文章的保护

如果直接访问黑客文章详情页（如 `/posts/hacker-1-crypto`），在未激活黑客模式的情况下会看到：

```
🔒 访问受限
此内容需要通过隐秘模式验证后才能查看。
在设置面板中连续点击站点名称 5 次，然后在搜索框中输入密钥。
[返回首页]
```

页面会通过 MutationObserver 监听黑客模式状态，一旦激活黑客模式，保护门会自动消失，显示文章内容。

## 9. 标签隔离规则

黑客模式下的标签系统具有严格的隔离机制，确保普通标签与黑客标签完全分离。

### 标签显示规则

进入黑客模式后，标签的显示遵循以下规则：

| 模式 | 普通标签 | 黑客标签 |
|------|----------|----------|
| 普通模式 | 正常显示 | 完全隐藏 |
| 黑客模式 | 完全隐藏 | 正常显示 |

### 文章与标签的完全隔离

黑客模式下的内容隔离不仅限于标签，**文章和标签是同步隔离的**：

| 模式 | 普通文章 | 普通标签 | 黑客文章 | 黑客标签 |
|------|----------|----------|----------|----------|
| 普通模式 | 正常显示 | 正常显示 | 完全过滤 | 完全过滤 |
| 黑客模式 | 完全过滤 | 完全过滤 | 正常显示 | 正常显示 |

- **普通模式**：只展示普通文章和普通标签，黑客文章和黑客标签被完全过滤，在任何页面均不可见。
- **黑客模式**：只展示黑客文章和黑客标签，普通文章和普通标签被完全过滤，在任何页面均不可见。

### 标签隔离范围

标签隔离规则覆盖博客中所有标签相关的位置：

- **文章卡片标签**：每篇文章卡片上的标签列表，仅显示当前模式对应的标签。
- **标签页**（`/tags`）：标签聚合页面，仅列出当前模式对应的标签及其文章数量。
- **侧边栏标签**：侧边栏中的标签筛选区域，仅显示当前模式对应的标签。
- **搜索标签筛选**：搜索功能中的标签筛选下拉，仅显示当前模式对应的标签。

### 文章列表隔离

文章列表同样遵循隔离规则：

- **首页文章列表**：普通模式仅展示普通文章，黑客模式仅展示黑客文章。
- **标签筛选列表**：点击任意标签后展示的文章列表，仅包含当前模式对应的文章。
- **分页**：文章总数和分页数量仅计算当前模式下的文章，不会混入对方模式的文章。

### 搜索功能隔离

搜索功能同样遵循完整的隔离规则：

- **普通模式下搜索**：只能搜索到普通文章，**搜不到任何黑客文章**。即使黑客文章标题或内容中包含搜索关键词，也不会出现在搜索结果中。
- **黑客模式下搜索**：只能搜索到黑客文章，**搜不到任何普通文章**。即使普通文章标题或内容中包含搜索关键词，也不会出现在搜索结果中。
- **搜索建议和自动补全**：同样遵循隔离规则，仅提示当前模式下的文章标题和标签。

### 刷新后恢复

刷新页面后，博客退回普通模式，标签系统自动恢复正常：

- 黑客标签被完全隐藏。
- 普通标签恢复正常显示。
- 所有标签相关页面和功能回到默认状态。

> **注意**：标签隔离与文章隔离是同步的。进入黑客模式后，普通文章和普通标签同时隐藏；退出黑客模式后，两者同时恢复。这两个隔离机制由同一个状态管理，不会出现文章切换了但标签没切换的情况。

## 10. 常见问题

### Q: 我忘记密钥了怎么办？

A: 查看项目根目录的 `.env` 文件，其中 `HACKER_SECRET_KEY` 的值就是密钥。如果 `.env` 文件不存在或密钥为空，请通过 TUI 工具重新设置。

### Q: 连续点击站点名称 5 次没有反应？

A: 请确保：
1. 点击的是设置面板中的站点名称，不是页面顶部的 Logo
2. 在 2 秒内完成 5 次点击（速度要快）
3. 点击后回到首页，观察右下角是否出现 `▮▯▮▯▮` 像素标识

### Q: 输入密钥后没有切换，而是执行了搜索？

A: 这说明你没有先触发像素 loading 标识。请先完成第 2 步（连续点击 5 次），看到 `▮▯▮▯▮` 标识后，再打开搜索框输入密钥。

### Q: 输入密钥后提示"未找到相关文章"？

A: 密钥错误。系统会执行正常的文章搜索，搜索框中输入的内容作为搜索关键词。请确认密钥是否正确。

### Q: 黑客模式切换后文章没有变化？

A: 请确认：
1. `src/content/hacker-posts/` 目录下有 `.md` 文件
2. 文章卡片正确设置了 `data-post-type` 属性
3. 浏览器控制台没有报错

### Q: 刷新页面后黑客模式消失了？

A: 这是正常行为。黑客模式不持久化，每次刷新都需要重新触发。详见第 6 节「会话规则」。

### Q: 如何管理黑客文章？

A: 使用 TUI 工具，启动时选择「黑客版」模式，即可管理黑客文章（新建、编辑、删除、迁移）。详见 [TUI 使用教程](./02-TUI使用教程.md)。

### Q: 密钥修改后多久生效？

A: 需要重新构建部署（`npm run build` + Git 推送）。Cloudflare Pages 构建完成后，新密钥立即生效。

### Q: 右下角的健康检查浮动球去哪了？

A: 健康检查浮动球已被移除，健康检查功能已迁移至设置面板中。打开设置面板（点击右上角齿轮图标）即可查看站点健康状态。

### Q: 可以在手机上触发黑客模式吗？

A: 可以。在手机浏览器中打开设置面板，点击站点名称 5 次（快速点击），然后点击搜索图标，输入密钥。操作方式与桌面端相同。

## 11. 密钥修改流程

当你需要更换黑客模式访问密钥时，请按照以下步骤操作。修改密钥后，旧密钥将在重新部署后立即失效。

### 第 1 步：修改密钥

你可以通过以下任一方式修改密钥：

- **TUI 工具**（推荐）：运行 `npm run tui`，选择「黑客版」→「① 站点管理」→「3) 隐秘模式访问密钥设置」，输入新密钥并确认
- **手动修改**：编辑 `.env` 文件的 `HACKER_SECRET_KEY` 和 `wrangler.toml` 的 `[vars]` 部分，确保两处密钥一致

### 第 2 步：重新构建

在项目根目录执行构建命令：

```bash
npm run build
```

构建过程会使用 djb2 算法对新密钥进行哈希处理，并将新的哈希值嵌入到生成的 HTML 文件中。构建完成后，`dist/` 目录下的产物即为包含新密钥哈希的静态文件。

### 第 3 步：重新部署

将修改后的代码推送到 GitHub 仓库，Cloudflare Pages 会自动检测到更新并触发部署：

```bash
git add .env wrangler.toml
git commit -m "更新黑客模式密钥"
git push
```

等待 Cloudflare Pages 部署完成（通常 1-3 分钟），你可以在 Cloudflare Dashboard 中查看部署进度。

### 第 4 步：验证新密钥

部署完成后，使用新密钥验证黑客模式是否正常工作：

1. 打开你的博客网站
2. 打开设置面板（点击右上角齿轮图标）
3. 连续点击站点名称 5 次，确认出现 `▮▯▮▯▮` 像素标识
4. 按 Ctrl+K 打开搜索框，输入**新密钥**并按回车
5. 确认页面成功切换为黑客终端风格

你也可以通过浏览器开发者工具验证：按 F12 打开 Elements 面板，查看 `<html>` 标签的 `data-hacker-hash` 属性，其值应为新密钥的 djb2 哈希值。

### 重要提醒

> **警告**：重新部署完成后，旧密钥将**立即失效**。请确保在部署前已经记下新密钥，并通知所有需要访问黑客模式的人员。如果旧密钥仍有用户在使用，他们将无法再进入黑客模式。
