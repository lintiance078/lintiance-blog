## 1. 依赖安装与启动

### 依赖安装

TUI 工具依赖已在项目 `package.json` 中配置，无需额外安装：

```bash
# 在项目根目录执行
npm install
```

```bash
# 方式一：npm 脚本
npm run tui

# 方式二：直接运行
node tui/index.js
```

## 3. 新建文章操作

### 步骤

1. 在主菜单选择 `📝 新建文章`，按 Enter
2. 输入**文章标题**（必填），按 Enter 确认
3. 输入**标签**，逗号分隔（如 `Astro,教程,前端`），按 Enter 确认
4. 输入**文章摘要**（可选，直接回车跳过），按 Enter 确认
5. 系统自动生成 Markdown 模板文件
6. 自动打开编辑器（优先 Publii，回退记事本）

### 生成的文件

- 路径：`src/content/posts/{slug}.md`
- slug 自动根据标题生成（URL 友好格式）
- frontmatter 自动填充标题、标签、日期、摘要

### 模板格式

```markdown
---
slug: "my-post-slug"
title: "我的文章标题"
date: "2025-06-15"
tags: ["标签1", "标签2"]
summary: "文章摘要"
cover: ""
cover_ascii: ""
word_count: 0
---

# 我的文章标题

> 在这里撰写文章正文...
```

## 4. 编辑文章操作

### 步骤

1. 在主菜单选择 `✏️ 编辑文章`
2. 从列表中选择要编辑的文章（↑↓ 导航，Enter 确认）
3. 系统自动打开编辑器

### 编辑器优先级

1. **Publii**（如果已安装）→ 自动检测以下路径：
   - `C:\Program Files\Publii\Publii.exe`
   - `C:\Program Files (x86)\Publii\Publii.exe`
   - `%LOCALAPPDATA%\Publii\Publii.exe`
2. **系统默认编辑器**（如果 Publii 未找到）
3. **记事本**（最终回退）

> ⚠️ **重要**：仅使用 Publii 作为 Markdown 编辑器，**禁止使用其站点导出功能**。

## 5. 图片处理操作

### 子菜单

```
┌─ 图片处理 ──────────────┐
│ 🗜️  压缩图片              │
│ 🎨 单张图片转 ASCII       │
│ 📦 批量转换旧图片为 ASCII  │
│ 📊 查看图片统计           │
│ ↩️ 返回主菜单             │
└─────────────────────────┘
```

### 5.1 图片压缩

1. 选择 `🗜️ 压缩图片`
2. 输入图片路径（相对于 `public/assets/images/`）
3. 系统使用 Jimp 进行有损压缩（默认质量 80%，最大宽度 1920px）
4. 显示压缩前后大小对比

### 5.2 单张图片转 ASCII

1. 选择 `🎨 单张图片转 ASCII`
2. 输入图片路径
3. 确认风险提示："转换后将删除原图片，是否继续？"
4. 系统执行转换：
   - 读取图片 → 灰度化 → 缩放 → 逐像素映射字符
   - 生成 ASCII 文本文件到 `public/assets/ascii/`
   - 删除原图片文件
5. 输出可嵌入 Markdown 的格式

### 5.3 批量转换旧图片

1. 选择 `📦 批量转换旧图片为 ASCII`
2. 系统显示当前图片统计和阈值配置
3. ⚠️ **风险提示**：显示将转换的图片数量，提示画质下降
4. 输入 `y` 确认执行
5. 系统自动批量转换：
   - 仅转换超过 `oldImageDays` 天的旧图片
   - 新图片（≤ 阈值天数）保留原图
   - 逐张显示转换进度
6. 完成后显示转换总数和释放空间

### 5.4 自动转换阈值配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| imageThreshold | 12000 | 图片总数达到此值时触发自动转换 |
| autoConvertEnabled | true | 是否启用自动转换 |
| oldImageDays | 30 | 超过此天数的图片视为"旧图片" |

可在 TUI 设置中调整。

## 6. 一键流水线操作

### 完整流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 系统自检  │ ──▶ │ 本地构建  │ ──▶ │ Git 推送  │
└──────────┘     └──────────┘     └──────────┘
   失败终止          失败终止          成功！
```

### 操作步骤

1. 选择 `🚀 一键流水线`
2. 输入提交信息（可选，直接回车使用默认信息）
3. 等待执行：
   - **第一步**：系统自检（检查 Git、Wrangler、Astro、Pagefind 等）
   - **第二步**：`npm run build` 构建静态网站
   - **第三步**：`git add -A && git commit && git push`
4. 完成后显示结果

### 关键规则

- **自检不通过** → 直接终止，不会构建，不会推送
- **构建失败** → 终止，输出错误日志，不会推送
- **无文件变更** → 跳过 Git 提交
- **推送成功** → GitHub 自动触发 Cloudflare Pages 部署

### 说明

- Cloudflare Pages 需要提前在后台绑定 GitHub 仓库
- 本工具不调用 Cloudflare 部署 API
- 推送后等待 1-3 分钟，Pages 自动完成部署

## 7. 数据管理操作

### 子菜单

```
┌─ 数据管理 ──────────────┐
│ 📤 同步文章元数据到 D1    │
│ 🏷️  同步标签到 D1         │
│ ⚙️ 写入 KV 站点配置       │
│ 🔗 管理友链列表           │
│ ↩️ 返回主菜单             │
└─────────────────────────┘
```

### 7.1 同步文章到 D1

从本地 Markdown frontmatter 读取元数据，写入 D1 数据库：
- 收集所有 `.md` 文件的 frontmatter
- 生成 SQL INSERT 语句
- 通过 `wrangler d1 execute` 执行

### 7.2 同步标签到 D1

统计所有文章的标签，写入 D1 标签表。

### 7.3 写入 KV 配置

支持修改的 KV 键：
- `site_config` - 站点基本信息
- `theme_config` - 主题配置
- `layout_config` - 布局配置
- `features_config` - 功能开关
- `footer_config` - 页脚配置

### 7.4 管理友链

添加友链：输入名称 → URL → 描述 → 写入 KV

## 8. 自检功能说明

### 自检级别

| 级别 | 执行时机 | 检查项数 |
|------|----------|----------|
| 基础检查 | 启动时自动执行 | 5 项 |
| 完整检查 | 手动执行 / 高危操作前 | 10 项 |
| 流水线检查 | 一键流水线执行前 | 12 项 |

### 检查项详解

| 检查项 | 失败级别 | 处理方案 |
|--------|----------|----------|
| Node.js 版本 < 18 | 错误 | 升级 Node.js |
| 项目目录缺失 | 错误 | 确认在正确目录下运行 |
| package.json 缺失 | 错误 | 确认项目完整性 |
| wrangler.toml 占位符 | 警告 | 部署前替换为实际 ID |
| node_modules 缺失 | 错误 | 运行 `npm install` |
| Git 未安装 | 错误 | 安装 Git |
| Git 仓库未初始化 | 错误 | 运行 `git init` |
| Git Remote 未配置 | 错误 | 配置 origin |
| Wrangler 不可用 | 警告 | D1/KV 功能不可用 |
| Wrangler 未登录 | 警告 | 运行 `npx wrangler login` |
| Publii 未找到 | 警告 | 回退系统默认编辑器 |
| 图片数量达阈值 | 警告 | 建议运行批量转换 |
| Astro 不可用 | 错误 | 运行 `npm install` |
| Pagefind 不可用 | 警告 | 搜索索引无法生成 |

## 10. 常见报错排查

### 10.1 "Wrangler 未登录"

```
[✗] Wrangler 登录: 未登录
[→] 解决方案: 运行 npx wrangler login 登录 Cloudflare 账号
```

执行 `npx wrangler login`，在浏览器中完成 Cloudflare 授权。

### 10.2 "Git Remote 未配置"

```
[✗] Git Remote: 未配置 origin
[→] 解决方案: 运行 git remote add origin <仓库地址> 配置远程仓库
```

在 GitHub 创建仓库后，执行：
```bash
git remote add origin https://github.com/你的用户名/仓库名.git
```

### 10.3 "node_modules 缺失"

```
[✗] node_modules: 缺失
[→] 解决方案: 请运行 npm install 安装依赖
```

### 10.4 "图片文件过大"

```
[✗] 图片文件过大: photo.jpg (26.5MB)，超过 Cloudflare Pages 单文件 25MB 限制
```

解决方案：
1. 使用 TUI 的图片压缩功能
2. 手动压缩图片后重新添加
3. 将图片转换为 ASCII 字符画

### 10.5 "构建失败"

常见原因：
- TypeScript 类型错误 → 检查代码修改
- 路径引用错误 → 确认文件路径正确
- 依赖缺失 → 运行 `npm install`
- 磁盘空间不足 → 清理磁盘

### 10.6 "Git 推送失败"

常见原因：
- 网络问题 → 检查网络连接
- 权限问题 → 检查 GitHub 仓库权限
- 分支冲突 → 先 pull 再 push
- 大文件问题 → 检查是否有超过 100MB 的文件
