## 1. 启动与双入口选择

### 启动方式

```bash
# 方式一：npm 脚本（推荐）
npm run tui

# 方式二：直接运行
node tui/index.js

# 方式三：使用一键脚本
双击 oneclick_scripts\05_TUI工具\start_tui.bat
```

### 启动画面

启动后，TUI 自动执行基础自检，检查 Node.js 版本、项目目录、依赖等关键项。自检通过后，显示 ASCII 艺术字 Banner "林天策 Blog"。

### 双入口模式选择

TUI v2.0 支持双入口模式，启动后首先显示选择界面：

```
┌─ 选择站点模式 ───────────┐
│ 林天策 Blog【普通版】      │
│ 林天策 Blog【黑客版】      │
└───────────────────────────┘
```

- **普通版**：管理 `src/content/posts/` 目录下的文章，面向所有访客
- **黑客版**：管理 `src/content/hacker-posts/` 目录下的文章，仅通过隐秘黑客模式访问

> 选择后，后续所有操作（文章管理、站点管理）都在所选模式下进行。不同模式下的文章库**完全独立**。

## 3. 站点管理

选择 `① 站点管理` 进入子菜单：

```
┌─ 站点管理 ──────────────────────────┐
│ 1) 网站设置（名称/描述/标题/favicon）  │
│ 2) 风格管理（外观样式参数）            │
│ 3) 隐秘模式访问密钥设置（仅黑客版）     │
│ ↩️ 返回主菜单                        │
└──────────────────────────────────────┘
```

### 3.1 网站设置

依次输入以下信息（直接回车跳过不修改的项）：

| 设置项 | 说明 | 修改位置 |
|--------|------|----------|
| 站点名称 | 显示在设置面板和页面的标题 | 写入 `wrangler.toml` 的 `SITE_TITLE` |
| 站点描述 | SEO 描述文字 | 写入 `wrangler.toml` 的 `SITE_DESCRIPTION` |
| 浏览器标题 | 浏览器标签页标题 | 写入 `wrangler.toml` |
| favicon 路径 | 网站图标路径 | 写入 `wrangler.toml` |

> **注意**：修改后需要重新构建部署才能生效。

### 3.2 风格管理

可调整的 CSS 样式参数：

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 主题色 | 网站主色调 | `#6366f1`（紫色） |
| 卡片圆角 | 文章卡片圆角大小 | `16px` |
| 正文字号 | 页面正文字体大小 | `16px` |
| 暗色背景 | 暗色模式背景色 | `#0f172a` |
| 最大宽度 | 内容区域最大宽度 | `1200px` |

> **注意**：通过 TUI 直接修改 `src/styles/global.css` 中的 CSS 变量。修改后需要重新构建部署才能生效。

### 3.3 隐秘模式访问密钥设置（仅黑客版）

黑客版模式下，站点管理菜单会多出第 3 项：`隐秘模式访问密钥设置`。

- 显示当前密钥的脱敏形式（如 `****r2`）
- 输入新密钥 → 确认密钥 → 密钥写入 `.env` 和 `wrangler.toml`
- 密钥存储在 `.env` 文件中，**不会出现在浏览器源码中**
- 修改后需要重新构建部署才能生效

> **安全警告**：`.env` 文件已在 `.gitignore` 中忽略，**切勿将 `.env` 提交到 Git 仓库**。

## 4. 文章管理

选择 `② 文章管理` 进入子菜单：

```
┌─ 文章管理 ───────────────┐
│ 1) 管理文章              │
│ 2) 发布文章              │
│ ↩️ 返回主菜单             │
└──────────────────────────┘
```

### 4.1 管理文章（列表/删除/隐藏/迁移）

选择 `1) 管理文章` 后，显示文章列表（包含普通文章和黑客文章，标注类型）：

```
┌─ 文章列表 ───────────────────┐    ┌─ 操作 ───────────────┐
│ 1. [普通] 我的第一篇文章       │    │ 🗑️  删除文章          │
│ 2. [普通] 技术分享             │    │ 👁️  隐藏/显示文章      │
│ 3. [黑客] 系统日志 #0          │    │ 🔄 迁移文章（普通↔黑客）│
│ 4. [黑客] 加密技术 #1          │    │ 📝 编辑文章            │
│ ↩️ 返回文章管理                │    └───────────────────────┘
└──────────────────────────────┘
```

**操作步骤**：
1. 在左侧列表中选择一篇文章（方向键导航，Enter 确认）
2. 在右侧操作菜单中选择要执行的操作

**各项操作说明**：

| 操作 | 说明 |
|------|------|
| 删除文章 | 确认后**永久删除** `.md` 文件，不可恢复 |
| 隐藏/显示文章 | 在 frontmatter 中添加/移除 `hidden: true`，隐藏后前台不显示 |
| 迁移文章 | 将文章从普通库迁移到黑客库，或反之。文件会物理移动到另一个目录 |
| 编辑文章 | 打开系统默认编辑器编辑 `.md` 文件 |

> **警告**：删除操作不可逆，请在确认前仔细核对文章标题。

#### 文章迁移（普通↔黑客库）

在文章列表中选择一篇文章后，可以在操作菜单中选择 `🔄 迁移文章（普通↔黑客）` 进行迁移操作。

**迁移流程**：
1. 在左侧文章列表中选择要迁移的文章
2. 在右侧操作菜单中选择 `🔄 迁移文章（普通↔黑客）`
3. 系统自动判断当前文章所在库，并显示迁移目标（如"普通 → 黑客"或"黑客 → 普通"）
4. 确认迁移后，系统执行以下操作：
   - 将 `.md` 文件从 `src/content/posts/` 移动到 `src/content/hacker-posts/`（或反之）
   - 自动更新文件的 frontmatter 元数据
   - 刷新文章列表显示

**迁移注意事项**：
- 迁移后文章 URL 会发生变化（普通文章和黑客文章使用不同的路由前缀）
- 迁移操作会**物理移动文件**，不会保留副本
- 迁移后的文章不会自动出现在对方模式的首页，需要重新构建部署
- 黑客文章在普通模式下不可见，反之亦然
- **标签跟随迁移**：文章迁移时，该文章的所有标签会**同步切换归属**。例如，将一篇普通文章迁移到黑客库后，该文章原有的标签会自动从普通标签库移除，并添加到黑客标签库中；反之亦然。系统会自动处理标签库的增删，无需手动干预

### 4.2 发布文章（完整表单编辑）

选择 `2) 发布文章` 后，系统会以表单形式引导你逐项填写。以下为完整输入流程：

> **模式提示**：发布文章时，界面顶部会显示当前模式指示器（如 `[普通版]` 或 `[黑客版]`），明确标识文章将发布到哪个文章库。在「标签」输入步骤中，界面还会提示标签将归属到对应的标签库（普通标签库或黑客标签库）。

#### 第 1 步：输入文章标题

```
┌─ 文章标题 ─────────────────────────┐
│                                    │
└────────────────────────────────────┘
```

- **必填**，不能为空
- 直接回车 = 取消操作
- 标题会用于生成 URL slug（如 `我的第一篇文章` → `我的第一篇文章`）

#### 第 2 步：输入标签

```
┌─ 标签（使用 # 号分隔） ──────────────┐
│                                    │
└────────────────────────────────────┘
```

- **标签规则**：使用 `#` 号分隔，如 `#技术#安全#教程`
- **连续 `##` 视为两个独立标签**：如 `#前端##React` 会生成 `前端` 和 `React` 两个标签
- 直接回车 = 不加标签

#### #井号标签规则

标签使用 `#` 号作为分隔符，系统会自动将标签字符串解析为数组存入 frontmatter。

**基本规则**：
- 输入格式：`技术#教程#JavaScript`
- 解析结果：`["技术", "教程", "JavaScript"]`
- 以 `#` 开头，多个标签之间用 `#` 分隔
- 连续 `##` 视为两个独立标签，如 `#前端##React` → `["前端", "React"]`
- 直接回车跳过，不添加标签

**标签在 frontmatter 中的存储**：
```yaml
tags:
  - 技术
  - 教程
  - JavaScript
```

**标签的用途**：
- 文章分类和筛选
- SEO 关键词优化
- 相关文章推荐
- 标签云/标签页展示

#### 标签归属与隔离

TUI 双入口模式下的标签系统采用**归属绑定 + 自动隔离**机制，确保不同模式下的标签完全独立。

##### 标签自动归属

在 TUI 中发布文章时，标签会根据当前入口模式自动归属到对应的标签库：

- 在「普通版」入口创建文章 → 标签自动归属到**普通标签库**（`tags` 数据源）
- 在「黑客版」入口创建文章 → 标签自动归属到**黑客标签库**（`hacker-tags` 数据源）

> 无需手动指定标签归属，系统会根据当前模式自动处理。

##### 文章迁移时标签跟随切换

当文章执行**迁移操作**（普通 ↔ 黑客库）时，文章的标签也会同步跟随文章进行归属切换：

- **普通 → 黑客**：文章从 `src/content/posts/` 迁移到 `src/content/hacker-posts/` 时，该文章的所有标签自动从普通标签库移除，并归入黑客标签库
- **黑客 → 普通**：文章从 `src/content/hacker-posts/` 迁移到 `src/content/posts/` 时，该文章的所有标签自动从黑客标签库移除，并归入普通标签库

这意味着标签的归属始终与文章所在库保持一致，不会出现标签"挂空"或"错位"的情况。

##### 标签隔离规则

系统在展示层面强制执行**标签隔离**，确保两种模式的内容完全不交叉：

| 场景 | 可见标签 |
|------|----------|
| 普通版前台页面 | 仅显示普通标签库中的标签 |
| 黑客版前台页面 | 仅显示黑客标签库中的标签 |
| TUI 普通模式文章管理 | 仅列出普通标签库中的标签 |
| TUI 黑客模式文章管理 | 仅列出黑客标签库中的标签 |

**隔离带来的好处**：
- 黑客版文章和标签不会在普通版页面中泄露
- 两个模式的标签体系完全独立，互不干扰
- 标签云和标签筛选页面在两种模式下展示不同的内容

### 文章置顶功能

TUI 工具中暂不支持直接设置置顶。如需置顶文章，请在 frontmatter 中手动添加：

```yaml
pinned: true
```

置顶文章会在 Card-List 布局中优先显示。不同布局对置顶的处理方式：

| 布局 | 置顶行为 |
|------|----------|
| Masonry 瀑布流 | 置顶文章在顶部显示，其余瀑布流排列 |
| Grid 均等网格 | 置顶文章在顶部显示 |
| List 纯列表 | 置顶文章在列表顶部 |
| Card-List 混合 | 置顶卡片数量可配置（1-5张），仅显示置顶文章 |
| Timeline 时间轴 | **不执行置顶逻辑**，强制按发布时间倒序 |

> **TUI 操作提示**：在文章管理的「编辑文章」功能中，可以直接修改 frontmatter 添加 `pinned: true` 来置顶文章。编辑完成后保存文件，重新构建部署即可生效。**注意**：Timeline 时间轴布局会忽略 `pinned: true` 标记，始终按发布时间倒序排列。

### 文章导入 .md 文件

TUI 支持在发布文章时直接导入外部 Markdown 文件，无需手动复制粘贴内容。

**操作步骤**：
1. 进入 `文章管理 → 发布文章`
2. 按表单依次填写标题、标签、作者等信息
3. 在「正文 Markdown 内容」步骤中，输入 `.md` 文件的**完整绝对路径**
4. 系统会自动检测：如果输入以 `.md` 结尾且文件存在，则读取文件全部内容作为正文

**示例**：
```
┌─ 正文 Markdown 内容 ────────────────┐
│ D:\articles\my-draft.md             │
└─────────────────────────────────────┘
```

**支持的导入方式**：
- 直接输入文件路径：`D:\articles\my-draft.md`
- 拖拽文件到终端窗口（部分终端支持自动填充路径）
- 复制文件路径后在终端中粘贴

**注意事项**：
- 文件路径必须是**绝对路径**，相对路径可能无法正确识别
- 文件编码建议使用 **UTF-8**，否则可能出现中文乱码
- 导入的正文内容会与表单中填写的标题、标签、摘要等元数据合并生成新文章
- 导入的文件本身不会被修改或删除

### 4.4 文章发布流程

完整的文章发布流程如下：

**发布新文章步骤**：
1. 在主菜单选择 `② 文章管理`
2. 在文章管理子菜单选择 `2) 发布文章`
3. 按表单提示依次填写：标题 → 标签 → 作者 → 头像 → 日期 → 摘要 → 正文
4. 确认信息无误后，系统生成 `.md` 文件并保存到当前模式对应的目录（普通版保存到 `src/content/posts/`，黑客版保存到 `src/content/hacker-posts/`）

**手动指定发布时间**：
- 在第 5 步"发布时间"输入框中输入自定义日期，格式为 `YYYY-MM-DD`（如 `2025-06-15`）
- 默认值为当天日期，直接回车使用默认值
- 可用于发布过往文章（补录历史内容）或预发布未来文章（定时发布）
- 日期会写入 frontmatter 的 `date` 字段

**设置作者头像**：
- 在第 4 步"作者头像路径"输入框中输入头像路径，如 `/assets/avatar.png`
- 头像文件需提前放置在 `public/assets/` 目录下
- 直接回车跳过，不设置头像
- 头像路径会写入 frontmatter 的 `authorImage` 字段

**发布前预览**：
- 发布完成后，在项目根目录运行 `npm run dev` 启动本地开发服务器
- 在浏览器中访问 `http://localhost:4321` 预览文章效果
- 检查文章排版、图片显示、标签是否正确
- 确认无误后，通过 TUI 的 `③ 部署` 功能推送到线上

## 5. 部署功能

选择 `③ 部署` 后，系统执行一键流水线：

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 系统自检  │ ──▶ │ 本地构建  │ ──▶ │ Git 推送  │
└──────────┘     └──────────┘     └──────────┘
   失败终止          失败终止          成功！
```

### 操作步骤

1. 输入提交信息（直接回车使用默认信息 `Update: 日期 时间`）
2. 等待执行完成
3. 部署成功后，GitHub Actions 自动触发 Cloudflare Pages 构建部署

### 部署验证

部署成功后，TUI 会提示验证建议：
1. 等待 2-5 分钟后访问 Cloudflare Pages 控制台
2. 检查构建状态是否为 "Success"
3. 访问线上页面确认配置和文章元数据
4. 对比本地内容与线上内容是否一致

## 6. 操作按键说明

| 按键 | 功能 |
|------|------|
| `↑` `↓` | 导航菜单项 |

## 7. 常见报错排查

### 7.1 "Wrangler 未登录"

```
[✗] Wrangler 登录: 未登录
[→] 解决方案: 运行 npx wrangler login 登录 Cloudflare 账号
```

执行 `npx wrangler login`，在浏览器中完成 Cloudflare 授权。

### 7.2 "Git Remote 未配置"

```
[✗] Git Remote: 未配置 origin
[→] 解决方案: 运行 git remote add origin <仓库地址> 配置远程仓库
```

在 GitHub 创建仓库后，执行：
```bash
git remote add origin https://github.com/你的用户名/仓库名.git
```

### 7.3 "node_modules 缺失"

```
[✗] node_modules: 缺失
[→] 解决方案: 请运行 npm install 安装依赖
```

### 7.4 "图片文件过大"

```
[✗] 图片文件过大: photo.jpg (26.5MB)，超过 Cloudflare Pages 单文件 25MB 限制
```

解决方案：
1. 使用图片压缩工具压缩图片
2. 将图片转换为 ASCII 字符画
3. 使用外部图床托管大图

### 7.5 "构建失败"

常见原因：
- TypeScript 类型错误 → 检查代码修改
- 路径引用错误 → 确认文件路径正确
- 依赖缺失 → 运行 `npm install`
- 磁盘空间不足 → 清理磁盘

### 7.6 "Git 推送失败"

常见原因：
- 网络问题 → 检查网络连接
- 权限问题 → 检查 GitHub 仓库权限
- 分支冲突 → 先 pull 再 push
- 大文件问题 → 检查是否有超过 100MB 的文件

### 7.7 "TUI 界面显示异常"

常见原因：
- 终端窗口太小 → 建议调整到 80x24 以上
- 字体不支持 Unicode → 使用支持 Unicode 的终端（如 Windows Terminal）
- 编码问题 → 确保终端使用 UTF-8 编码

### 7.8 ".env 中缺少 HACKER_SECRET_KEY"

```
[✗] .env 中缺少 HACKER_SECRET_KEY
[→] 解决方案: 在 TUI 中选择黑客版 → 站点管理 → 隐秘模式访问密钥设置
```

或手动在 `.env` 文件中添加：
```
HACKER_SECRET_KEY=你的密钥
```
